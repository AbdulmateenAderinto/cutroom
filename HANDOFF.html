1Set up (once)

You need Homebrew. Then, in Terminal:

brew install node ffmpeg-full

ffmpeg-full rather than ffmpeg: Homebrew's plain ffmpeg has no zscale, vid.stab or rubberband, so HDR tone mapping would be refused and stabilizing/speed would use the weaker fallbacks.

git clone https://github.com/AbdulmateenAderinto/cutroom.git ~/cutroom
cd ~/cutroom && npm install

Already have a clone from earlier?

Update it instead:

cd ~/cutroom && git pull origin main && npm install

Optional: transcripts and captions

brew install whisper-cpp

Then download a speech model inside the app: clip panel → Smart tools → Transcribe.

2Run it

cd ~/cutroom && npm run dev

npm run dev hot-reloads UI changes. Restart it after changing anything in src/main or src/preload. To run a normal build instead: npm start.

3Make an installable app (.dmg)

cd ~/cutroom && npm run dist:mac

Output: dist/Cutroom-0.1.0-arm64.dmg (Apple Silicon) and dist/Cutroom-0.1.0.dmg (Intel). Open it and drag Cutroom to Applications.

  • Ad-hoc signed, not notarized. A .dmg you built yourself opens normally; one downloaded from elsewhere needs right-click → Open the first time.
  • FFmpeg is not bundled (licensing). Homebrew's FFmpeg is found automatically, even when started from Finder.
  • No Mac handy? On GitHub: Actions → “macOS app (.dmg)” → Run workflow. It runs all tests on a Mac runner, builds both .dmg files and attaches them to the run (cutroom-macos). It only runs when started by hand or on a v* tag.

4Connect Claude (AI control)

  1. In Cutroom: AI control (top bar) → tick Allow AI assistants to control Cutroom.
  2. Copy the snippet it shows:
    • Claude Desktop: Settings → Developer → Edit Config → paste the cutroom entry under mcpServers → restart.
    • Claude Code: run the claude mcp add … command it shows.
  3. Ask things like “Remove the silences in interview.mov and add boxed captions” or “Make a 30-second vertical cut with a crossfade between each clip”.

If you move or reinstall the app, copy the snippet again (the path changes). Details: docs/AI.md.

7Tests

npm test

Unit + real-FFmpeg export tests (270, about 2 minutes).

npm run test:e2e

Drives the real app through every feature (16 scripts, about 15 minutes) and compares the preview with the exported video.

npm run test:mcp

Connects the official MCP client and edits through the AI tools.

npm run dist:dir && npm run test:packaged

Checks a packaged build starts and the AI bridge works from inside it.

Screenshots and exported files from the tests go to tests/.output/.

8Known limits

Short version — the full list, with how each feature was tested, is in docs/STATUS.md.

  • Speed changes: sound is time-stretched and lands slightly early/late (≈ −50 ms at 0.25×, −30 ms at 0.5×, +8…15 ms at 2×). Normal speed is exact.
  • HDR tone mapping, LUTs, noise reduction, voice-over and the hardware encoder have not been tried with real Mac footage/hardware.
  • Noise reduction is export-only (use “Listen” to hear it). Speed ramps are stepped, not a smooth curve.
  • The export queue lives in the window: closing the app stops it. Parallel export has not been benchmarked.
  • The AI tools (MCP) don't cover the media manager (relink, collect, remove unused) yet.
  • .dmg not notarized; FFmpeg must come from Homebrew (Phase 5, §11).
  • Crossfade playback in the preview: smoothness at the cut has not been measured; a brief stutter is possible.

9Where things live

PathWhat
src/shared/The editing model and all maths shared by preview and export: model.ts, ops.ts, time.ts, exportPlan.ts, audio.ts, audioFx.ts, titles.ts, transitions.ts, color.ts, effects.ts, animation.ts, overlays.ts, markers.ts, captions.ts

src/renderer/React UI, the preview engine (preview/engine.ts), state and actions (state/), export queue (state/exportQueue.ts)
src/mcp/The stdio MCP bridge Claude launches
tests/unit/, integration/ (real exports), e2e/ (the real app)
docs/STATUS.mdEvery feature with how it was tested, plus limitations
docs/ARCHITECTURE.mdHow preview and export stay identical, timing model, export pipeline
docs/AI.mdSmart tools and AI control
The rule the code follows: anything that affects the picture or sound is computed once in src/shared/ and used by both the preview and the export, so they can't drift apart — and each feature has a test comparing the preview with the export. Keep it that way.

11What's next

Phase 5 needs your input before it can start. It was deliberately skipped.

Notarized release

Needs a paid Apple Developer account for a Developer ID certificate and notarization, so downloaded copies open without the right-click → Open step.

Bundled FFmpeg

Shipping FFmpeg inside the app means choosing a build and licence. An LGPL build can be bundled more freely but lacks libx264/libx265 (H.264/HEVC would then use Apple's hardware encoder only); a GPL build keeps them but makes the whole app GPL.

Other ideas

  • Smooth (curve) speed ramps.
  • AI tools for the media manager (relink, collect, remove unused).
  • An export queue that survives quitting the app.
  • Transitions on overlay tracks; per-shot colour matching.
  • Real-time noise reduction in the preview.
